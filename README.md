# Field Kit Manage

Back-office companion to **Datacom Field Kit** — an admins-only Dashboard home for the office: live crew, today's jobs, yesterday's recap, the week ahead, and a needs-attention list, all computed live from the same Supabase data Field Kit already collects.

- **Separate app.** Field Kit is not modified in any way; Manage only reads.
- **Admins only.** Sign in with your Field Kit account; non-admin accounts get a closed door.
- **Field Kit time data is never written.** Dashboard, Timesheets, and Schedule only read, and no view ever changes entries, timers, or pulls. Manage writes in four places: Company Management (gear icon — the company's own setup and the admin list), Projects, where admins manage the jobs themselves (create, edit, crew, close, soft-delete, restore) since v1.5 — plus, since v1.9, the Recycle bin's permanent purge of jobs whose 30 days are up, which runs through the same server-side function as the accounts (the browser itself never deletes a job), and — since v1.6 — the accounts themselves, through a small server-side function (add person, edit name, deactivate, delete, password reset), and — since v1.7 — the Customers directory: customers, their site locations, and the customer/site links stored on jobs, and — since v1.8 — the Materials area: the cable type and color lists Field Kit's dropdowns read, and the standard-materials catalog. Time data is never among them.
- **Live.** Realtime subscriptions plus a 5-minute refresh keep timers and flags current.
- **Print.** The Print brief button renders a one-page morning brief (at-a-glance, yesterday, week ahead, today's jobs, needs attention).
- **Timesheets.** A second view (Dashboard | Timesheets in the header): everyone's hours for a week or a pay period, click a person for their full day-by-day sheet, with print and CSV export.
- **Projects.** A third view: every job in one filterable, searchable list, and a per-project page with all-time totals, hours by person, and the full entry history.
- **Schedule.** A fourth view: the week as a board — every scheduled job on its days, multi-day jobs spanning, unstaffed jobs flagged, and an unscheduled tray for open jobs with no dates.
- **Customers.** A fifth view: the customer directory — each customer with its main address, primary contact, and notes, plus its site locations (own address, optional own contact, access notes), linked to its jobs by real ids. Renaming a customer or a site updates the text on its linked jobs, and the directory can be built in one click from the customer names already on jobs.
- **Materials.** A sixth view: the cable lists (types and colors) techs pick from in Field Kit — edited here and effective on the field side at the next load, with Field Kit's built-in fallback lists shown honestly when nothing custom is saved — plus the standard materials catalog (name, default unit, category), seeded in one click from the names the crew already logs. A later Field Kit update will offer the catalog to techs as quick-picks; the materials log itself stays free text.
- **Company Management.** A gear icon in the header opens the company using the app — its profile (name + logo), its people, accounts, and admin access, and its settings.
- **Jump.** Ctrl/Cmd+K jumps to any job, customer, or tech on the page.
- **Demo.** Add `?demo` to the URL to preview with sample data, no sign-in needed — the demo includes a full previous week so Timesheets has something to show.

## One-time setup

Run `supabase-manage-readonly.sql` (kept with the project plan) once in the Supabase Dashboard SQL Editor. It adds two SELECT-only policies so admins can read crew time entries and cable pulls. Until it runs, the app loads and shows projects, timers, and schedules, with a banner explaining that hours are waiting on the SQL.

For Jobs management (v1.5), also run `supabase-jobs-write.sql` once in the same SQL Editor. It is purely additive: admin-only insert/update rules on projects and add/remove rules on project crew — and deliberately no delete rule on projects, so removing a job in Manage is a restorable soft delete. (The permanent purge added in v1.9 does not use a delete rule either — it runs through the `manage-users` function; see below.) Until it runs, the job controls explain that the setup is needed and everything else works exactly as before.

For Users management (v1.6), deploy the `manage-users` Edge Function once: Supabase Dashboard → Edge Functions → Create a function named `manage-users` → paste the supplied `functions/manage-users/index.ts` → Deploy. Before deploying, check the editor shows the whole file — it is 316 lines, and its last lines are the error handler that returns a 500 JSON response (an editor once silently truncated a long paste, so this check matters). No SQL and no secrets to configure: the platform injects the keys, the service-role key never leaves the function, and every call checks that the caller is an admin. Until it is deployed, People & access works exactly as before and shows a setup note.

For the Customers area (v1.7), also run `supabase-customers.sql` once in the same SQL Editor. It is purely additive: it creates the `customers` and `customer_sites` tables (any signed-in user can read the directory; only admins can change it) and adds two nullable link columns, `customer_id` and `site_id`, to projects. Field Kit never reads the new tables, and its job saves name only the columns they have always named, so the links are left alone. It can be run before or after the app update. Until it runs, the Customers view shows a one-time-setup note and everything else works exactly as before.

For the Materials area (v1.8), cable needs nothing — the `cable_options` table and its admin rules have existed since Field Kit v5.2, and Manage simply uses them. For the materials catalog, run `supabase-materials-catalog.sql` once in the same SQL Editor: it creates the `materials_catalog` table (any signed-in user can read it; only admins can change it) and adds an admin read rule on the materials log so the catalog can be seeded from the crew's own history. Until it runs, the catalog section shows a one-time-setup note and the cable lists work exactly as before.

For the Recycle bin purge (v1.9), re-deploy the same `manage-users` function with the updated file (316 lines — re-check the editor shows the whole file). It gains two actions: `purge_expired`, which erases every job that has spent more than 30 days in the Recycle bin, and `purge_project`, which erases one such job and refuses any job not yet deleted or not yet expired. The function judges the 30 days against its own clock, records each purge first (so any Field Kit client still syncing drops its local copy), then deletes the job row so its child records — time entries, cable pulls, materials, IP assignments, switch data, technicians, crew — cascade away, exactly like Field Kit's own admin purge. No new SQL, and the browser still holds no delete power over jobs. Until the updated function is deployed, the bin's purge buttons explain the update and restoring works exactly as before.

For Company Management (v1.4), also run `supabase-company.sql` once in the same SQL Editor. It is purely additive: it creates the `company_settings` table (company name, logo, pay-period anchor) with a public read rule (the sign-in screen shows the branding before login) and admin-only write rules, and it lets admins grant or remove admin rights from inside Manage. Until it runs, Company Management shows a one-time-setup note and everything else works exactly as before.

## Version

v1.9 — The Projects Deleted filter becomes the **Recycle bin**, with a 30-day retention. A deleted job's row shows its name, customer, ticket, and deleted date, plus its state: "Restorable for N more days" with a Restore button, or — once the 30 days are up — "Expired — ready to purge", sorted so expired jobs sit on top. Inside the window there is no purge control anywhere, in the bin, the job page, or the gear menu: the retention is a guarantee, not a suggestion. Expired jobs collect under a **Purge expired (N)** button, and each expired row also has its own Purge. The confirm window names every job about to be erased and says plainly that all of its logged hours, materials, and cable records go with it and past timesheets will change; one deliberate tap on the red button runs it. Purging itself lives in the `manage-users` function (two new actions — the server computes the 30 days from its own clock and refuses anything live, undeleted, or unexpired), so the app's direct write sites are unchanged and the browser gains no delete power: a deleted job's history still counts in Timesheets for its whole 30 days, and only a purge rewrites it.

v1.8 — A sixth view, Materials. The cable card edits the types and colors in Field Kit's existing `cable_options` store — no setup, and changes reach the techs' dropdowns at their next load. When a kind has no saved rows the card shows Field Kit's built-in list as the effective one, offers to copy it in as editable rows, and warns that a first custom entry replaces the built-ins; removing the last saved entry restores them, and removals never touch pulls already logged. The materials catalog is a new table (`supabase-materials-catalog.sql`): standard items with a default unit and category, grouped by category, archived rather than deleted, with a "Build from materials history" seed that imports the distinct names (and each name's most-used unit) from the crew's own materials log, plus a usage count per item. The catalog is staged: Field Kit will offer it as quick-picks in a later Field Kit release; the log stays free text, so nothing a tech logs is ever blocked or rewritten by it. The write boundary grows on purpose: Manage now also writes `cable_options` (add/remove) and `materials_catalog` — time entries, timers, and pulls are still never written.

v1.7 — A fifth view, Customers: the customer directory. Each customer carries its main address, one primary contact, and notes, plus any number of site locations (own address, optional own contact, access notes). Jobs link to the directory by real ids (new `customer_id` / `site_id` columns on projects): the job form gains a directory picker that fills the customer/site text and stores the link — typing free text instead leaves the job unlinked, and the form says which state it is in — and a linked job's page shows a Customer chip that jumps to the directory entry. Renaming a customer or a site rewrites the text on its linked jobs, with the count reported. A “Build from existing jobs” button seeds the directory from the customer and site names already on jobs and links the matches. Customers and sites are archived (soft-deleted) rather than deleted, so links never dangle; archived entries restore from the Archived filter. Ctrl-K finds customers too. Needs the one-time `supabase-customers.sql` (see setup). The write boundary grows on purpose: Manage now also writes the two directory tables and the link columns on projects (create, edit, link, cascade, seed) — time entries, timers, and pulls are still never written.

v1.6.2 — People & access tidies up: every action for a person (Edit name, Reset password, Make/Remove admin, Deactivate/Reactivate, Delete) now lives in a single three-dot menu on the right of their row, so the list reads clean — just the person, their email, and their last sign-in. Guarded actions stay in the menu as disabled items with the reason underneath ("Your account", "Last admin") instead of notes under the row. Everything else behaves exactly as in v1.6.1.

v1.6.1 — Three Dashboard fixes. The recap now follows the last workday: the recap card, the Finished tile, the morning brief, and the recap-based Needs attention checks all read the most recent weekday, so on a Monday they show Friday's numbers and say so ("Last workday — Friday", "Finished Friday") instead of an empty Sunday; midweek they still say Yesterday. Palette picks now land from anywhere: choosing a job in the Ctrl-K palette opens that job in Projects whatever view you are on, and choosing a tech outside Timesheets takes you to their row in Live crew on the Dashboard. Blocks on the Live crew day timeline also gain a thin divider between entries, so back-to-back blocks read as separate entries.

v1.6 — Dashboard home + Timesheets + Projects + Schedule board + Company Management. New in 1.6: People & access manages the accounts themselves — Add person creates a real Field Kit account and shows a temporary password exactly once, to hand over in person; every person also gains Edit name, Reset password, Deactivate/Reactivate, and Delete. It all runs through the one-time `manage-users` Edge Function (see setup) — the browser never holds the service key. Deactivated people are badged in the list, keep all of their history, and drop out of crew pickers; an account with work history can't be deleted, and the app steers you to deactivating it instead. New in 1.5: Projects manages jobs — a New job button (jobs are created in Field Kit's exact shape: the creator is the owner, picked crew become member rows), and every job page gains a gear menu in its header card: Edit job and Manage crew open as floating windows (the owner shown fixed; add and remove members; someone with a timer running on the job is badged, and removing them never touches the timer), close/reopen acts straight from the menu, and Delete job opens a confirm window for the soft delete. Deleted jobs collect under a new Deleted filter in Projects with one-tap restore; permanent deletion stays impossible from Manage at this version (the 30-day Recycle bin purge arrives in v1.9). New in 1.4.1: the browser tab favicon follows the company logo set in Company Management — logo set, the tab wears the logo; no logo, the stock icon stays. New in 1.4: the gear icon in the header opens Company Management — company profile (name + logo, shown in the header, on the sign-in screen, and as a letterhead on printouts), people & access (grant or remove admin rights, with a last-admin guard), and company settings including the pay-period anchor (Timesheets reads the company value whenever the company is set up; the per-device value is the fallback). New in 1.3.2: the Print brief action moved out of the header into the view tabs bar as an icon-only printer button (still Dashboard only), and the home section was renamed from Oversight to Dashboard; the timesheet Print and CSV actions joined it in the tabs bar as matching icon buttons (Timesheets only). New in 1.3.1: hovering a block on a crew member's day timeline (Dashboard, Live crew) shows which job it was for, with the kind, times, and duration — a running block shows its elapsed time so far. (Job costing is a later phase, approved separately.)

## Timesheets

- **Periods.** Toggle between **Week** (Mon–Sun) and **Pay period** (14 days = two Mon–Sun weeks). ‹ › steps one week or one pay period at a time; **Current** jumps back to today.
- **Pay period anchor.** Pay periods count from an anchor date so the 14-day blocks line up with your real payroll cycle. It defaults to Mon Jan 5, 2026. Once the company is set up, the anchor is a company setting (Company Management → Settings) that applies to everyone — and the **Pay period starts** field shown in pay-period mode edits that same setting. Before company setup, the value is remembered per device instead.
- **Summary.** One row per person — day totals in week view, Week 1 / Week 2 in pay-period view — with drive hours and an overtime chip whenever a single week passes 40 h. Anyone on the clock right now counts in as "so far" with a live dot.
- **Detail.** Click a person: totals split by kind (Drive / On site / Remote / Shop), a day-total strip, then every entry day by day with job, ticket, times, hours, lunch, and notes.
- **Print & CSV.** Print gives the crew summary plus one page per person with hours. CSV downloads one row per entry (tech, date, job, customer, ticket, kind, start, end, hours, lunch, notes) for the period on screen — completed entries only, running timers are not included.
- Still read-only: timesheets never writes to Field Kit data. Older weeks load on demand when you page back beyond the most recent entries.

## Projects

- **List.** Every project (except deleted ones) with filter chips and counts — Active is the default; also Scheduled, Open, Overdue, Closed, All — plus a text search over job name, customer, and ticket number. Columns: job + customer, ticket, status chip, schedule ("Today", "Day X of Y", a date or range, "Ended <date>" for overdue, "—" when unscheduled), crew avatars, all-time total hours (live dot when a timer is running on the job), and last activity. Sorted by last activity, newest first. Click a row to open the project.
- **Status.** Derived, never stored: Closed › Overdue › In progress (a timer is running) › Worked today › Unstaffed (due today, nobody assigned) › Not started (due today, crew assigned, no time yet) › Scheduled › Open.
- **Manage (v1.5).** A New job button tops the list; each job page carries a gear icon in its header card — its menu opens Edit job and Manage crew as floating windows (owner shown fixed and not removable; timers badged, never touched), closes or reopens the job directly, or opens a confirm window for the soft delete. A **Recycle bin** filter (renamed from Deleted in v1.9) lists soft-deleted jobs with their deleted date and how many of their 30 restorable days remain; once a job's 30 days are up it can be purged permanently from the same list, through the `manage-users` function (see setup). Job writes need the one-time `supabase-jobs-write.sql` (see setup); before it runs, the controls show a setup note instead of failing.
- **Detail.** The full story of one job: header with customer · site · ticket, status, schedule, start date (earliest entry, or the project creation date), and the assigned crew; a totals strip (total hours + entry count, Drive / On site / Remote / Shop, cable pulled in feet + last pull date); **Hours by person** — each person's total with a kind-split stacked bar whose length is scaled to the top person's total; **History** — every entry grouped by day with day totals, kind pill, start–end times, lunch deductions, and notes, plus today's running timer as a live row; and the project's notes when set.
- **History depth.** Entries load up front capped at the newest 3,000. Opening a project page fetches that project's entries once (per project per session), merges them in, and re-renders, so long jobs show their complete history. No fetch happens in demo mode.
- **Printing.** The morning brief prints from the Dashboard and timesheets from the Timesheets tab; the Projects tab has no print output this round. With the Projects tab active, Ctrl+K picks a project to open its page.

## Schedule

- **Board.** The week (Mon–Sun) as a board: every job whose scheduled dates touch the week gets a card on its days, and multi-day jobs stretch across their days in shared lanes. ‹ › steps a week at a time; **This week** jumps back to the current week. Today's column is highlighted whenever it is in view.
- **Cards.** Job name, customer · ticket (the ticket never wraps mid-number), assigned crew as avatars + first names, a range caption with "Day X of Y" while a multi-day job is underway, and a status chip (In progress / Worked today / Closed / Overdue) once the job has touched today or a past day. A job with nobody assigned shows as a red card — "— nobody assigned —" — in any week.
- **Summary + tray.** A line above the board counts the week's jobs and its unstaffed jobs. Under the board, an **Unscheduled** tray lists the open jobs with no dates at all — hours logged so far and last activity, stalest first, with an amber note once a job has been quiet for 7+ days — so backlog never hides just because it has no dates.
- **Click-through.** Clicking any board card or tray row opens that project's page on the Projects tab.
- **Phone.** On narrow screens the board becomes a day-by-day list; a multi-day job appears once, on the day it starts, with its range caption.
- Still read-only — the board is computed from the same loaded projects, members, entries, and timers; it adds no queries and no writes.
## Company management

- **Where.** The gear icon in the header (between refresh and your avatar) opens Company Management. It is not a fifth tab — the four working views stay as they are, and no tab is highlighted while you are in it.
- **Profile.** Company name and logo. An uploaded logo is resized in the app (at most 512 px) and stored with the settings, so there is no file hosting to set up. A live preview shows the branded header and the print letterhead as you edit.
- **Branding.** Once a name and logo are saved, they appear in the app header (company name, with "Field Kit Manage" as a muted sub-line), on the sign-in screen, and as a letterhead on the morning brief and the timesheet printouts. Before setup, the FK branding is the fallback and printouts are unchanged.
- **People & access.** Everyone who has an account: name, email, last activity, and an Admin badge where it applies. **Make admin** and **Remove admin** write to the admin list directly. Two guards: the last admin can't be removed (the button disables, with a note saying why), and removing your own admin rights takes a second, confirming tap — after which Manage politely closes the door behind you. Since v1.6 it also manages the accounts themselves, through the `manage-users` function: Add person (a temporary password is shown once, to hand over), Edit name, Reset password, Deactivate/Reactivate, and Delete — with the same guard style (you can't deactivate or delete your own account, and the last admin is protected). An account with work history can't be deleted; deactivating closes it while keeping the history.
- **Settings.** The pay-period anchor as a company setting (see Timesheets) — one value for the whole company once set up.
- **The write boundary.** Company Management writes Manage's own company setup and the admin list directly, and manages accounts through the `manage-users` function (the only place the service key exists). (Since v1.5 the Projects view also writes — jobs and their crew only; see Projects. Time entries, timers, and pulls are never written anywhere in Manage.)
- **Demo.** `?demo` shows a fictional company (NorthPeak Integration) with controls that genuinely work against the in-memory demo data; nothing is kept.
